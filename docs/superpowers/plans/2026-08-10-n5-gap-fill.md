# N5 词量补缺 + 复合动词试点 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** N5 现有 607 词（动词80/名词411/形容词82/副词33/拟声词1），官方大纲粗估约 800 词，缺口约 193。本次目标：①在名词/形容词/副词/拟声词四个已有类别里补充新词，尽量逼近官方量级（但不强行凑数，以实际能验证的真实 N5 词汇为准）；②给 N5 试点加入复合动词（複合動詞）类别——**这是本计划里唯一一个新类别决策点**，需要在 Task 1 就先确认这个类别在 N5 是否真的有实质内容可收。

**Architecture:** 复用已验证四轮（N5/N4/N3 首轮 + N2 两轮）的流程：WebSearch + jisho.org 逐词核实等级（本次词表来源和 N5/N4/N3 首轮一样，需要网上采集，不是用户直接提供，所以要走完整的等级核实流程，不同于 N2 那两轮）；`scripts/generate-cards.js` 不实际调用（继续走 subagent 生成 + Claude Code 订阅额度）；`npm run validate` 不改。

**Tech Stack:** 纯前端静态站点、Node.js `--test`、WebSearch/WebFetch、Claude subagent。

## Global Constraints

- Schema和现有一致，不改 `scripts/validate-cards.js`
- 拟声词 `word` 必须等于 `kana`
- 复合动词（如果 Task 1 判定 N5 确实有内容可收）沿用动词 schema：`type`∈{五段,一段,サ变,カ变} + 可选 `transitivity`∈{自,他,自他}
- 例句难度必须是 N5 等级（简单句，です・ます体为主）
- **词表来源需要等级核实**（不同于 N2 阶段）：本次是自主采集，必须用 jisho.org 或同等工具核实每个候选词确实是 N5，不能只看某个网站的"N5"标签——延续 N3 阶段学到的教训（旧版 JLPT 等级和现行 5 级体系不对应）
- **跨文件/跨等级去重**：新词必须和 N5 现有 5 个子库、以及 N1-N4 已有的词汇零重叠（一个词不能同时是"N5 新词"又已经在任何等级出现过——这条比之前几轮更严格，因为这次是"补缺"而不是"新增类别"，新词本来就该是目前全站词库里完全没有的词）
- 跨文件兼类词的处理标准延续之前几轮：合法兼类词允许跨文件出现，但要在采集阶段就列出清单，生成阶段主动写不同例句
- 目标词量不预设强制指标，官方大纲的"约800"只是参考，实际以能验证的真实词汇为准，宁缺毋滥

## Task 0（决策前置）：判断 N5 复合动词类别是否值得做

**这不是一个常规实施任务，是一个需要真实判断的调研步骤，放在 Task 1 之前完成，判断结果决定后续 Task 是否包含复合动词部分。**

複合動詞（前一动词连用形+后一动词，如取り上げる）通常是 N3-N2 阶段才大量出现的语法点，N5 阶段教材里复合动词数量可能很少甚至接近于零（N5 学习者语法基础还不足以处理复合动词的语义组合）。

- [ ] 用 WebSearch 查找是否存在权威来源专门列出"N5 复合动词"或"初级复合动词"。如果只能找到个位数（比如 5 个以内）真正有 N5 等级标注的复合动词，如实报告这个数字，不强行凑数，也不要因为数量少就放弃——按照本项目一贯的"诚实小类别"原则（N4/N5 阶段的拟声词都只有1个，也照样保留了），只要是真实存在的就收录。
- [ ] 如果连 1 个都找不到有 N5 等级标注的复合动词，如实报告"N5 没有复合动词类别"，本计划后续任务里跳过复合动词相关的 Task（不新建 `cards-n5-compound.json`、不新建 `n5-compound.html`、不改 `word-type-picker.html` 的 `HAS_COMPOUND`），只做名词/形容词/副词/拟声词的补缺。

- [ ] **Step 1: 搜索权威 N5 词汇表，本次要覆盖官方大纲全量（不只是之前采集时找到的子集）**

用 WebSearch 找权威来源（JLPTsensei 的 N5 各词性专页、MLC 的 N5 词表、Bunpro 等），目标是尽量覆盖官方大纲的 N5 全量词汇，不只是之前几轮已经用过的那批。

- [ ] **Step 2: 排除已在全站词库里出现过的词**

程序化核对候选词表和以下全部文件的 `word` 字段：`data/cards*.json` 里所有 N1-N5 的现有文件（不只是 N5 自己的 5 个文件，因为目标是全站零重叠的新词）。

```bash
node -e "
const fs = require('fs');
const allFiles = fs.readdirSync('data').filter(f => f.startsWith('cards') && f.endsWith('.json'));
const existing = new Set();
for (const f of allFiles) {
  for (const c of require('./data/'+f).cards) existing.add(c.word);
}
// 候选词表逐个核对，排除 existing.has(word) 为 true 的
"
```

- [ ] **Step 3: 用 jisho.org 逐词核实等级**

对每个候选词核实 JLPT 等级标注，确认是 N5（不是旧版分级体系混入的 N4/N3 词）。

- [ ] **Step 4: 词性自查 + 跨文件兼类词清单**

延续 N3/N4 阶段确立的标准：名词看 を/が/の，な形容词看「〜な＋名词」，副词看是否修饰动词/形容词而非自身做谓语，拟声词看是否有真实拟态结构。明确列出所有合法跨文件兼类词。

- [ ] **Step 5: 写入文件 + 提交**

```bash
git add data/raw-words-n5-*-gap.txt data/raw-words-n5-compound.txt
git commit -m "data: 采集 N5 补缺词表(名词/形容词/副词/拟声词" + 视情况 "/复合动词)"
```

在 commit message 里写清楚各文件词条数、复合动词类别的调研结论（Task 0 的判断结果）、以及跨文件兼类词清单。
