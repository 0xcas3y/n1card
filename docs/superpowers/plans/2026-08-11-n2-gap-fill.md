# N2 词量补缺 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** N2 现有 1045 词（动词200/名词310/形容词229/副词75/拟声词106/复合动词125），官方大纲粗估约 6000 词，缺口约 4955。本次是"N5→N4→N3→N2"补缺序列的最后一站，目标：①在名词/形容词/副词/拟声词/动词五个已有类别里补充新词，尽量逼近官方量级（不强行凑数）；②复合动词类别已存在（125词，N2本轮首创的独立类别），本次调研是否还有额外真实词条可以扩充这个已有类别（不是决定要不要建，而是决定要不要扩）。

**Architecture:** 复用已验证四轮（N5/N4/N3 gap-fill）的方法论：WebSearch 多源采集 + jisho.org/Bunpro 双源等级核实（冲突保守排除，Bunpro 用 `__NEXT_DATA__` 结构化字段解析，不用 AI 文本摘要）+ 全站零重叠去重（word 和 kana 双字段）+ subagent 生成 + `npm run validate` 不改。**心理预期**：前三轮经验反复证明公开可验证的真实词量远低于官方估计（N5缺口193实际补5词，N4缺口912实际补28词，N3缺口2466实际补68词），本轮缺口4955不代表真能补上千词，以实际能验证的为准；但由于N2本身官方大纲量级最大，预期本轮绝对产出会明显高于前三轮。

**Tech Stack:** 纯前端静态站点、Node.js `--test`、WebSearch/WebFetch、Claude subagent。

## Global Constraints

- Schema不变，不改 `scripts/validate-cards.js`
- 拟声词 `word` 必须等于 `kana`
- 复合动词沿用动词schema：`type`+可选`transitivity`，助记法优先用真实词素分解
- **例句难度必须是 N2 等级**：可用较复杂的被动/使役/敬语/复合助词/书面语表达，词汇不能超N1（即N1以下含N2本身词汇都允许出现在例句里，只有真正N1专属的生僻词才算超纲——延续 N3 阶段学到的教训：审查时不要把"允许出现的低一级或同级词汇"错当成缺陷，必须先看清 Global Constraints 里明确写的词汇上限是"不超过上一级"，不是"只能用本级词"）
- **全站零重叠**：新词不能和 N1-N5 任何现有文件的 `word` 重复；`kana` 重叠如果对应不同汉字（真实同音异形词，比如型/肩/方 かた）不算重复，只有真正的同一个词的写法变体（比如 支払い vs 支払）才算重复要排除
- 等级核实用 jisho.org + Bunpro 双源交叉确认，冲突保守排除；注意 Bunpro 页面可能出现"A#"教材deck编码或推广横幅，不是真实等级标注；jisho.org 单源的 JLPT 标注对常见词有时会不可靠/过时（N3阶段发现"上司""対応""制服"等常见词被 jisho 错标 N1，但站内已有先例证明是 N2），如果 jisho 单源标注和站内已有词卡的既有分类冲突，以站内已上线、已过审的先例为准，不要仅凭单一来源就下判断
- 复合动词扩充：只收集全站零重叠的全新词条，不要求达到某个具体数字，如果调研后发现新增空间很小（比如个位数或零），如实报告
- 跨文件兼类词标准延续之前几轮：合法兼类词允许跨文件出现，生成阶段主动写不同例句避免重复
- 目标词量不预设强制指标，宁缺毋滥
