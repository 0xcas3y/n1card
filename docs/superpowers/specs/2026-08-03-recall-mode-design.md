# 回忆模式 + 学新批次改 60 + 顽固单词库 — 设计文档

**日期**：2026-08-03
**状态**：草案（待用户确认）
**前置**：`2026-07-11-batch-learn-timegate-design.md`（现有 30 词/批 + 时间窗 + 强制测验 + 一般复习）、`2026-07-16-n1n2-adj-onomatope-design.md`（词性扩展）

## 1. 目标 & 动机

现有复习入口只有两个：🌅 早复习（次日+次次日"不熟"词，四选一测验）、🔁 一般复习（全部学过的词，按简化遗忘曲线权重抽样，自由刷卡或测验）。

本次新增第三种复习入口 **🧩 回忆模式**，核心是"主动回忆"而非"被动识别"：
1. 有汉字读音的词，先隐藏读音强迫自己回忆，再揭示+朗读巩固
2. 没有汉字读音的词（纯假名词，如拟声词），改成回忆词义
3. 追踪每个词性板块被完整复习过几轮（"完成次数"），给用户一个宏观进度感
4. 反复想不起来的词进入独立的**顽固单词库**，日常复习中额外加强，直到稳定掌握才移出

同时把"学新"的批次大小从 30 改为 60（与洗脑模式的 `baseGroup=60` 对齐，`plan.js` 里其实已经有这个精度）。

**非目标**（YAGNI，本 spec 范围外）：
- 完整 SM-2/FSRS 间隔算法（顽固单词库的进出规则是简单计数器，不是间隔算法）
- 回忆模式的每日配额是否要和"学新批次"共享同一个时间窗限制——**不做**，回忆模式随时可用，同一般复习/早复习
- 跨词性统一顽固库（顽固库按词性板块分别维护，不做"动词的顽固词也出现在形容词复习里"这种跨库联动）
- 顽固单词库的手动管理界面（增删查看列表）——先只做自动进出机制，管理界面下一轮再说

## 2. 学新批次 30 → 60

- `plan.js` 的 `computeQuota(totalDays, baseGroup = 30)` 学新场景调用点，`baseGroup` 从 30 改为 60（洗脑模式已经在用 60，逻辑本身不用改，只改调用参数）
- `BATCH_SIZE` 常量（`plan.js` 里 §6.1 定义的、供 `hub.js`/`app.js` 引用的那个）30 → 60
- 连续打卡天数解锁的"批数"逻辑不变（1/6/13/14 天等边界不变），只是每批的词数从 30 变 60，所以每日总词数上限从 30/60/90 变成 60/120/180
- 强制测验题池同步变成 60 词（一批学完仍然强制测验，逻辑不变，只是池子变大）
- 影响范围：仅"学新"批次。早复习/一般复习/新增的回忆模式都不受这个常量影响（各自独立配额，见 §4）

## 3. 回忆模式流程

### 3.1 入口 & 池

- 等级页新增 🧩 回忆模式 卡片，常驻显示，随时可点开（不受学习时间窗限制，同一般复习）
- 池 = 该词性板块**全部已学过的词**（`status` 为 `known` 或 `unknown`，排除从没学过的），与一般复习共享同一个"已学过"判定
- 每次进入回忆模式，从"本轮复习进度指针"继续抽取本次会话的词（默认一次会话 60 词，不足 60 就把剩余的全部抽出）——不是随机抽样，是**顺序游标**，保证"轮完一遍"这件事可判定（见 §5）

### 3.2 单词处理分支

对池中每一个词，先判断 `word !== kana`（有独立汉字读音）还是 `word === kana`（纯假名，比如拟声词、部分名词/形容词）：

**A. 有汉字读音的词**（动词/形容词/名词/副词中的大多数）：
1. 正面只显示汉字写法（`word`），读音区域留空/打码
2. 停留 `hideDuration` 秒（设置项，可选 1/2/3 秒，默认 2 秒）——这段时间用户自己回忆读音
3. 时间到 → 揭示读音（`kana`），同时朗读 `word` 的 TTS，重复 `ttsRepeatCount` 次（设置项，默认 2 次）
4. 朗读完 → 等待用户滑动：左划=想不起来，右划=掌握（交互同现有卡片滑动）

**B. 纯假名词（无独立汉字读音）**：
1. 正面显示 `word`（假名本身）
2. 义项区域留空，停留 `hideDuration` 秒——用户自己回忆意思
3. 时间到 → 揭示 `meanings`（不涉及朗读环节，因为没有"读音"这个维度）
4. 揭示完 → 等待用户滑动：左划=想不起来，右划=掌握

两条分支共用同一套"卡片外壳"（正面→倒计时→揭示→滑动），只是揭示的内容（读音+朗读 / 释义）不同。

### 3.3 滑动后的记账

- 右划（掌握）：
  - 若该词当前在顽固单词库里 → `stubbornStreak[id]++`；若 `stubbornStreak[id] >= 3` → 移出顽固单词库，清空计数
  - 若不在顽固单词库 → 不做特殊记账，走现有 `Progress.mark(id, 'known')`
- 左划（想不起来）：
  - 走现有 `Progress.mark(id, 'unknown')`
  - 若该词不在顽固单词库 → 加入顽固单词库
  - 若已经在顽固单词库 → `stubbornStreak[id] = 0`（打断连续右划计数）

**顽固单词库的入库规则不限于回忆模式**——学新时初次滑左（不熟）也会触发同样的入库逻辑（复用同一个"记一次不熟"钩子），回忆模式内滑左同样入库。出库只能通过回忆模式内连续 3 次右划（早复习/一般复习里的滑动不参与 `stubbornStreak` 计数，避免规则太分散）。

## 4. 顽固单词库

- 数据结构：每个词性板块一份 `stubbornSet`（保存 id 列表）+ `stubbornStreak`（id → 连续右划计数，仅回忆模式内更新）
- **日常复习中的加强**：一般复习 (`computeGeneralReviewPool`) 的权重公式追加一条——若 `id` 在 `stubbornSet` 内，权重固定为 8（高于现有 `unknown` 权重 5，低于封顶 4 的 `known` 情况不适用，8 是全局最高档），确保顽固词被抽中的概率明显更高
- 移出：仅在回忆模式内连续 3 次右划触发（见 §3.3）
- 首页/回忆模式入口可以显示"顽固词 N 个待攻克"这种小角标（UI 细节，非本 spec 强制要求，实现时顺手加）

---

## 5. 回忆模式的"完成一轮"与轮次计数

- 每个词性板块维护 `recallCyclePosition`（游标，指向"已学过词"列表里下一个要复习的位置）+ `recallCycleCount`（完整轮完几次）
- 每次回忆模式会话：从 `recallCyclePosition` 开始按顺序取够一次会话的词量（默认 60，池子不够就取到池尾）
- 会话内每个词无论滑左滑右都算"复习过一次"，游标前移
- 游标到达池尾（覆盖了当前"已学过词"的全部）→ `recallCycleCount++`，游标归零重新开始
- 池子会随着继续"学新"而变大（新学的词加入已学过池），不影响已经产生的 `recallCycleCount`，只影响下一轮游标遍历的总长度
- 首页/回忆模式入口展示"该词性已完整复习 N 轮"

## 6. 设置项

`SettingsPanel` 新增两个滑块（沿用现有 TTS 语速滑块的样式）：
- 隐藏时长：1s / 2s / 3s（三档选择，非连续滑块也可以，按钮组更直观）
- 朗读次数：1-4 次（默认 2）

设置项存到现有 `Progress._settings`（每个词性板块各自的 localStorage key 下），不做跨板块统一设置。

## 7. 技术改动范围

### 7.1 `plan.js`
- 学新批次 `baseGroup` 调用点改 60
- 新增 `computeRecallSession(learnedIds, position, size=60)`：按游标顺序切一批，返回 `{ cardIds, nextPosition, cycleCompleted }`

### 7.2 `app.js`
- `Progress`：新增 `stubbornSet`/`stubbornStreak`/`recallCyclePosition`/`recallCycleCount` 的读写方法，持久化进现有 progress localStorage 结构（每个词性板块独立文件已经是独立 localStorage key，天然隔离）
- 新增 `RecallMode`（参考现有 `BrainwashMode`/`QuizMode` 的结构）：渲染卡片外壳、倒计时、揭示、TTS 调用（复用现有 `TTSEngine`）、滑动记账
- `computeGeneralReviewPool` 权重公式追加顽固词加权
- `SettingsPanel` 新增两个设置项 UI

### 7.3 `hub.js` / 等级页
- 新增 🧩 回忆模式 常驻卡片，展示"顽固词 N 个"+"已复习 N 轮"

### 7.4 各 `n1-*.html`
- 不需要新文件，`RecallMode` 作为 `app.js` 内的新状态复用现有卡片视觉

## 8. 边界 & 细节

| 情况 | 行为 |
|---|---|
| 已学过词为 0（还没学新） | 回忆模式入口禁用，提示"还没有学过的词" |
| 会话中途退出 | 已经处理过的词的记账（滑动结果、游标前移）保留；未处理的词留到下次会话继续，不回退游标 |
| 一批词全是"纯假名"或全是"有汉字" | 正常按各自分支处理，不强制混合 |
| 顽固词同时也是"今天刚学的新词" | 不特殊处理，正常参与顽固库逻辑（新学词第一次就滑左，直接入库） |
| 拟声词板块无"已掌握/不熟"以外的第三态 | 复用现有二态 `Progress.mark`，回忆模式不引入新状态机 |

## 9. 测试

### 9.1 单元测试
- `computeRecallSession`：游标越过池尾时正确 wrap 并标记 `cycleCompleted`；池子扩大后不影响已产生的 cycle 计数
- 顽固库进出：滑左入库、连续 3 次右划出库、中途滑左打断计数归零
