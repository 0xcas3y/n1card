## 1. 目标 & 动机

**核心诉求（用户原话）**：
> "我想尽可能让背单词变的简单，就是每天划卡复习，可以回忆模式，之前那套早复习，晚学习的每天打卡太复杂了，需要简化"

两个问题要同时解决：

1. **结构性断层**：现有"学新批次+时间窗+早复习+周复习+一般复习"这套机制（`hub.js`/`plan.js` 驱动）**只服务于每个等级的动词页面**（`n1.html`～`n5.html`）。这几个月扩充的名词/形容词/副词/拟声词/复合动词——占全站词库的大多数——用的是完全独立的 `SIMPLE_MODE` 页面（如 `n2-noun.html`），自由滑卡+可选测验，没有打卡、没有间隔复习保护，跟动词那套机制零关联（各自独立的 `localStorage` 进度键）。
2. **流程太复杂**：早晚双打卡（🌙晚学新 + 🌅早复习）、强制四选一测验通关、固定时间窗（晚8点-凌晨1点）、周复习（固定7天）、一般复习（加权随机）——五六个概念叠在一起，用户觉得繁琐。

**非目标**（YAGNI，本次不做）：
- 不做真正的 FSRS/SM-2 完整算法（本设计用固定阶梯，不是动态难度系数）
- 不改数据文件结构或验证脚本
- 不做跨设备同步（仍然是纯 `localStorage`，单设备）
- 不做"手动管理不熟词库"的增删界面
- 独立的词性浏览页面（如 `n2-noun.html` 现有的自由滑卡）保留作为参考/自由浏览用途，不强制删除，但不再是"打卡"入口

## 2. 架构变更：统一词池 + 统一进度存储

### 2.1 现状

每个词性文件是一个独立页面，独立 `LEVEL_KEY`（如 `n2`、`n2-noun`、`n2-adj`），独立 `localStorage` 进度：`n1card:progress:${LEVEL_KEY}`。同一等级内，动词的"已掌握"跟名词的"已掌握"毫无关系。

### 2.2 新架构

**统一词池**（运行时合并，不改数据文件）：每个等级建一个卡片聚合层，把该等级所有词性文件（`cards-n2.json`/`cards-n2-noun.json`/`cards-n2-adj.json`/`cards-n2-adverb.json`/`cards-n2-onomatope.json`，N2 再加 `cards-n2-compound.json`）在运行时 fetch 后拼接成一个数组，每张卡片附加 `category` 字段（`verb`/`noun`/`adj`/`adverb`/`onomatope`/`compound`）。

**复合 ID**：各词性文件内部 `id` 各自从 1 开始编号，互相冲突（如动词文件和名词文件都有 `id=1`）。合并后，进度存储和一切引用改用复合键 `${level}:${category}:${id}`（如 `n2:noun:311`）代替裸 `id`。

**统一进度存储**：新 `localStorage` 键 `n1card:progress2:${level}`（用新键名，不覆盖旧的 `n1card:progress:${LEVEL_KEY}`，避免和现有独立页面的进度混淆——旧页面继续读旧键，新统一流程读新键，见 §7 迁移策略）。每条进度记录：

```js
{
  "n2:noun:311": {
    intervalStage: 3,           // 0-5，对应 1/3/7/14/30/90 天
    nextReviewAt: 1723334400000,// 下次到期时间戳
    lastReviewedAt: 1722816000000,
    firstLearnedAt: 1722000000000,
    graduated: false            // 90天档滑对一次后置 true，仍偶尔出现在综合池但不再是复习主力
  }
}
```

**综合池跨等级**：`n1card:progress2:*` 按等级分开存（沿用现有"每等级一个 key"的惯例，方便清理/隔离），"综合"模式下运行时合并读取全部等级的进度做统一到期计算，不建单独的全局大 key。

## 3. 核心每日循环（取代早晚双打卡）

**入口**：`index.html` 首页改为一个"今日滑卡"入口（原来的 🌙/🌅 两张卡片合并为一张）。

**流程**：
1. 打开应用 → 点击"开始今日滑卡"
2. 会话内容 = **新词 + 到期复习词混合**一批：
   - 新词部分：按今日额度（沿用现有"累计打卡满10天+1批，上限3批，每批60词"的成长曲线，`computeBatchesAllowed` 逻辑不变）从"推荐词性"里取词。推荐顺序：动词→名词→形容词→副词→拟声词（N2 复合动词顺序待定，默认排在名词之后），当前词性全部学完才轮到下一个；用户可随时手动切换词性（UI 加一个词性选择器，类似现有等级切换下拉框）
   - 到期复习部分：从 `intervalStage` 到期队列取词，范围可选 **当前主攻**（当前等级+当前词性）或 **综合**（跨等级跨词性全部到期词），默认当前主攻
   - 两部分随机打散混在一起滑
3. 滑卡交互（复用现有卡片滑动手势）：
   - **右滑 = 记得**：新词 → 首次进入间隔阶梯（`intervalStage=0`，1天后到期）；到期复习词 → `intervalStage` 前进一档
   - **左滑 = 不熟**：新词 → 留在本次会话池中稍后再次出现（不写入进度，直到右滑通过才算"学过"）；到期复习词 → `intervalStage` 打回 0（1天后再考）
4. 滑完这批（所有词都被右滑过一次）= **当天打卡**，一次性的，不再区分早晚
5. **取消固定时间窗**，随时可以开始今日滑卡

**移除的概念**：
- 🌙/🌅 早晚双打卡 → 合并为一次
- 强制四选一测验通关 → 滑卡手势本身就是判定，不再有单独的测验关卡
- 晚8点-凌晨1点学习窗口 → 取消
- 📆周复习（固定7天）→ 被统一到期队列吸收，「掌握」的词到了对应间隔天数自然会出现在"到期复习"里，不再是独立机制
- 🔁一般复习（加权随机非强制）→ 不再需要，到期词每天自动出现在主流程里；额外想练用回忆模式（见 §4）

## 4. 回忆模式（独立可选，不影响算法进度）

跟"今日滑卡"完全分开的入口，随时可用，纯巩固/重温，**不读写 `intervalStage`**。

**取词范围**：当前主攻 / 综合 / 自由指定（手动选等级+词性，类似 `word-type-picker.html` 现有的选择方式）。

**两种子模式**，选定范围后乱序排列，逐词处理（每个词处理完再进下一个，不是"整批放一轮再放下一轮"）：

**A. 看着复习**（视觉+听觉）：
- 每个词播放 3 遍音频（TTS 朗读 `word`）
- 第 1、2 遍：屏幕上不显示中文释义（可以显示 `word`/`kana`）
- 第 3 遍：显示中文释义

**B. 听力/通勤复习**（纯音频，免看屏幕）：
- 每个词播放 3 遍音频
- 第 1、2 遍之间留间隔（设置项：3秒 或 5秒，用户可调）
- 第 3 遍：改为朗读中文释义（TTS 中文），而不是重复读日语词

两种模式共用一套"逐词3连播"骨架，差异只在"要不要看屏幕"和"第3遍读什么"。

## 5. 间隔重复算法

```
阶梯（intervalStage 0-5）：1天 → 3天 → 7天 → 14天 → 30天 → 90天
```

- 到期复习时右滑（记得）→ `intervalStage += 1`（封顶 5）；若已在 5 档且再次右滑 → `graduated = true`，退出主力到期队列，但仍以低频出现在"综合池"里（具体频率沿用现有 `computeGeneralReviewPool` 的加权随机思路，作为"综合池"内部的兜底供给，不单独占用"今日滑卡"的到期配额）
- 到期复习时左滑（不熟）→ 不管当前在第几档，`intervalStage = 0`（1天后再考），`graduated` 复位为 `false`
- `nextReviewAt` = 右滑/左滑发生时刻 + 对应天数

新词首次右滑通过（进入间隔阶梯）等价于"到期复习答对一次"，从 `intervalStage=0` 开始（1天后进入到期队列）。

## 6. 数据迁移

**触发时机**：用户首次进入新的"今日滑卡"流程时，对该等级做一次性迁移（每个等级独立触发，不是全局一次性）。

**迁移规则**（读旧的 `n1card:progress:${LEVEL_KEY}`，写新的 `n1card:progress2:${level}`）：
- 旧 `status === 'known'` → 新 `intervalStage = 3`（14天档），`nextReviewAt = now + 14天`
- 旧 `status === 'unknown'` → 新 `intervalStage = 0`（1天档），`nextReviewAt = now + 1天`
- 旧数据里没有进度记录的词（`unseen`）→ 不生成新记录，等用户在新流程里真正学到才创建
- 迁移只做一次（迁移后写一个 `n1card:migrated:${level}` 标记位，避免重复迁移覆盖用户后续的新数据）
- **只影响动词**（现有 `hub.js` 体系下的 `n1.html`～`n5.html`）——因为只有动词页面之前有 `known`/`unknown` 状态记录；名词/形容词/副词/拟声词/复合动词页面（`SIMPLE_MODE`）虽然也有自己的 `status` 记录（滑卡时用户标记的），同样需要按上述规则迁移，只是它们是从各自独立的 `n1card:progress:${LEVEL_KEY}`（如 `n1card:progress:n2-noun`）分别读取合并进新的 `n1card:progress2:n2`

## 7. 页面结构变化

- `index.html`：早晚两张卡片 → 合并成一张"今日滑卡"卡片；打卡日历从三态（🟡金/🟢半/⚪无）简化为两态（✅完成/⚪未完成）
- 新增统一滑卡会话页面（复用现有 `${level}.html` 的卡片渲染/滑动组件，但改为读取合并后的统一词池+统一进度，通过 URL 参数传入本次会话的复合 ID 列表）
- 新增回忆模式页面/弹层（独立入口，不挂在 `hub.js` 的 `DayView` 下）
- 原有的词性专属页面（`n2-noun.html` 等）**保留**，作为自由浏览/参考用途继续可访问，但首页不再引导用户从这里"打卡"——它们各自的 `SIMPLE_MODE` 滑卡+测验功能不变，只是跟新的统一进度体系解耦（各自的旧 `localStorage` 进度键不再被新流程写入，二者数据来源在迁移那一刻分叉）
