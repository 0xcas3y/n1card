# 分批学习 + 强制测验 + 时间窗 — 设计文档

**日期**：2026-07-11
**状态**：草案
**前置**：`2026-04-18-n1card-design.md`、`2026-04-23-review-mode-design.md`（当前 hub.js/plan.js/app.js 的既有实现）
**范围**：仅 n1/n2/n3/n4/n5 词卡（"动词板块"），不涉及 onomatope、grammar 模块
**明确排除**（下一轮单独 brainstorm）：词库品类扩展（形容词/副词/综合高频词）+ 用户自选词性入口——见 §9

---

## 1. 目标 & 动机

现有的"学新"是一次性发一整批配额（30/60/90 词）、滑完直接回首页，中途没有任何反馈点，也没有"你现在学到哪了"的阶段感——用户反馈是"没有目标的感觉"。

本次改造要解决三件事：

1. **有明确阶段目标**：把学新拆成固定 30 词一"批"，每批学完立刻有一个"通关"动作（强制测验），而不是学完一大坨才在第二天早上被动测。
2. **有节奏感的强制时间窗**：晚 8 点-凌晨 1 点是唯一能"学新"的时段，把"每天固定时段学习"变成产品强约束，而不是靠自觉。
3. **复习更主动**：除了现有次日早强化复习，新增一个随时可用的"一般复习"入口，按遗忘曲线权重把老词（尤其是学过又没复习的、以及一直不熟的）重新swap 进来。

**非目标**（YAGNI，本 spec 范围外）：
- 词库扩展到形容词/副词/综合高频词、词性自选（子项目 B，下一轮单独做）
- 完整 SM-2/FSRS 间隔曲线——一般复习的"权重"是简化版启发式，不是真正指数间隔算法
- 批次大小可配置（固定 30，不给用户调）
- 强制测验的及格线/最低正确率门槛——测验"做完"即算通关，不卡分数（和现有 onomatope quiz 通关逻辑一致）
- 学习窗口时间可配置——固定 20:00–01:00，不做设置项
- 跨设备同步

---

## 2. 现状 → 改造点对照

| 环节 | 现状 | 改造后 |
|---|---|---|
| 学新交付方式 | 一次性发 `computeQuota()` 词数（30/60/90），滑完即完成 | 固定按 30 一批发，滑完一批 → 强制测验 → 用户选择继续/结束 |
| 学新后的反馈 | 无，直接回首页，等第二天早复习 | 当场强制四选一测验（复用现有 `QuizMode`） |
| 每日学新上限 | 由连续打卡天数解锁（10 天 +1 组，上限 3 组）—**保留不变** | 同左，只是把"组"从"一次性词数"变成"可分批消费的批次数" |
| 学习可用时间 | 任意时间 | 仅 20:00–01:00 可以"学新"；其余时间"开始学习"入口锁住 |
| 早复习（🌅） | 次日+次次日"不熟"词，四选一 | 不变，随时可做，早上高亮提醒 |
| 复习入口数量 | 只有早复习 + 周复习 | 新增 🔁 一般复习：全部历史学过的词，按权重随时抽取 |
| 打卡判定 | 完成学新=晚打卡，完成早复习=早打卡 | 不变（一般复习不参与打卡） |

## 3. 分批学习流程

```
20:00–01:00 内，等级页点「开始学习」
  ↓
动态抽一批 30 个「未学过」的词（沿用 computeLearnQueue，quota 改按 30 分批发）
  ↓
滑卡定难易（左=不熟 / 右=已掌握，Progress.mark 不变）
  ↓
30 个滑完 → 强制通关测验（复用 QuizMode，四选一，题池＝这一批 30 词全部）
  ↓
测验做完（不卡分数）→ 选择页：
  · 继续下一批 —— 前提：今日已消费批次 < 今日允许批次（由连续打卡天数解锁，1/2/3 批）
                     且当前仍在 20:00–01:00 窗口内
  · 去复习刚才这批里滑「不熟」的词（可选，走自由刷卡，不强制）
  · 结束，返回首页
```

**当日晚打卡**：完成 ≥1 批「滑卡 + 通关测验」即算今晚打卡完成（不要求刷满当日全部批次上限）。

**批次上限沿用现有配额逻辑**：连续打卡天数 1–6 天→1 批/天，7–13 天→2 批/天，≥14 天→3 批/天（`computeQuota` 现有的 `groups` 计算，见 §6.1）。

## 4. 时间窗门禁

**规则**：`isLearnWindowOpen(now)` = 本地小时 `hour >= 20 || hour < 1`（20:00:00 – 00:59:59）。

**窗口内**（20:00–01:00）：
- 等级页显示「开始学习」入口（可发新批次）
- 「一般复习」「早复习」入口同时可用

**窗口外**（其余所有时间）：
- 「开始学习」入口置灰/隐藏，改为提示：`⏰ 现在不是学习时间 / 学习窗口：晚8点-凌晨1点 / 请晚一点再来~`
- 「早复习」「一般复习」两个复习入口**不受影响**，随时可点开

**边界情况**：
- 若用户在窗口内开始一批滑卡，滑到一半跨过 01:00 —— 不中断当前批次，允许滑完+测完；但测完后的"选择页"里「继续下一批」按钮此时应按最新时间重新判断，若已出窗口则禁用，只保留"复习刚才的/结束"
- 学新 session 的 URL 直接访问（比如收藏了 `?session=learn` 链接）也要在窗口外拦截，不能绕过入口按钮

## 5. 两种复习

### 5.1 🌅 早强化复习（沿用现有机制，不变）

- 池：`computeMorningPool` —— 昨天 + 前天 cohort 里仍是「不熟」的词
- 形式：四选一测验（`QuizMode`）
- 早上首页高亮提醒，但不锁时间，随时可点开做
- 完成 → 早打卡

### 5.2 🔁 一般复习（新增）

- **池**：全部历史"学过"的词（`status` 为 `known` 或 `unknown`，排除从没学过的）
- **权重算法**（简化版遗忘曲线，非真 SRS 间隔）：
  ```
  weight(card):
    若 status == 'unknown'      → 固定权重 5
    若 status == 'known'        →
      daysSince = (now - max(masteredAt, lastWeeklyReviewAt, lastSeen)) / 86400000
      weight = clamp(daysSince / 3, 0.5, 4)     // 越久没见权重越高，封顶 4，保底 0.5
  ```
- **抽样**：加权随机不放回，抽一批（默认 20 个，比学新批次略小，因为是复习不是学新）
- **呈现**：默认走自由刷卡（复用现有 Router 滑卡视图），用户可切换成测验模式（复用 `QuizMode`）
- **入口**：等级页固定按钮，20:00–01:00 之外也能点
- **不生成 cohort，不影响打卡**，纯补充练习
- 答题/滑动仍走现有 `Progress.mark` / `Progress.markQuiz`，状态机不变——测验答错「已掌握」词会掉回「不熟」，自然被下次一般复习/早复习捞回，不需要额外机制

## 6. 技术改动范围

### 6.1 `plan.js`（纯函数，新增）

- `BATCH_SIZE = 30`（常量，供 `hub.js`/`app.js` 引用）
- `computeBatchesAllowed(totalDays)`：把现有 `computeQuota` 内部的 `groups = Math.min(1+floor(t/10), 3)` 抽成独立导出函数；`computeQuota` 内部改为调用它（`baseGroup * computeBatchesAllowed(totalDays)`），保持原有输出不变，只是重构
- `computeGeneralReviewPool(progress, now, size = 20)`：按 §5.2 权重公式加权抽样，返回卡片 id 列表
- `isLearnWindowOpen(now = new Date())`：返回 boolean，供 hub.js/app.js 复用同一份时间判断逻辑

### 6.2 `hub.js`（DayView）

- 🌙 学新卡片：
  - 显示"今日批次进度"，如 `1/2 批已完成`（批次数 = `Math.floor(cohort.cardIds.length / BATCH_SIZE)`，不需要新 key，从现有 cohort 反推）
  - 时间窗外：按钮态从 `[开始]` 变成禁用提示态
- 新增 🔁 一般复习 卡片：常驻，不判断打卡状态，随时 `[开始]`

### 6.3 `app.js`（Router / QuizMode）

- 学新流程改为"发一批 → 滑完 → 立即调用 `QuizMode.start` 测这批 30 词 → 完成回调进入新的『选择页』视图（继续下一批 / 去复习刚才的不熟词 / 结束）"
- 新增"选择页"渲染（简单的三按钮界面，复用现有卡片视觉风格）
- 新增 `session=general-review` 入口：调用 `computeGeneralReviewPool` 取词、复用 Router 自由刷卡渲染 or `QuizMode`（视用户在入口页的选择）
- 学新相关 URL 入口（`?session=learn`）在渲染前先调用 `isLearnWindowOpen`，非窗口内直接渲染"锁定"提示页而不进卡片流程

### 6.4 `n1/n2/n3/n4/n5.html`

- 基本不需要结构大改，主要是新增"选择页"、"时间锁定提示页"、"一般复习入口按钮"的样式（在现有 `styles.css` 里加 class，不新建文件）

### 6.5 数据存储

不新增 localStorage key。全部复用现有结构：
- 批次完成数 = `cohort.cardIds.length / BATCH_SIZE`（现有 `PlanStore.completeLearn` 已支持同日多次调用合并 cardIds，天然支持"分批累加"）
- 一般复习不写入 cohort/session，只读现有 `Progress` 数据算权重，不持久化任何新状态

## 7. 边界 & 细节

| 情况 | 行为 |
|---|---|
| 当日批次已用完上限，还在窗口内 | 「开始学习」入口置灰，提示"今日学新已用完，明天再来"，一般复习/早复习仍可用 |
| 剩余"未学过"词不足 30 | 这一批按实际数量发（不足 30 也照常测验），测完后没有"继续下一批"选项（没词可发了） |
| 一般复习池为空（用户还没学过任何词） | 入口按钮禁用，提示"还没有学过的词可以复习" |
| 测验中途退出 | 沿用现有 `QuizMode.exit` 行为：不保存部分进度，批次不算完成，需重新开始这一批的测验 |
| 时间窗边界跨天（23:59→00:00） | `isLearnWindowOpen` 按小时判断，不受"今天/明天"日期字符串影响，00:xx 依然在窗口内 |
| 直接改系统时间/时区 | 不做防作弊处理，信任浏览器本地时间（和现有 Streak 逻辑一致） |

## 8. 测试

### 8.1 单元测试（Node `--test`，扩 `scripts/plan.test.js`）

- `computeBatchesAllowed(totalDays)` 与旧 `computeQuota` 的 `groups` 计算结果一致（1/6/7/13/14/20 天等边界值）
- `computeGeneralReviewPool`：unknown 词始终高概率入选；权重公式在多次采样下符合"权重越高、被抽中频率越高"的统计规律（用固定 seed 或统计断言，不要求精确值）
- `isLearnWindowOpen`：19:59→false，20:00→true，23:59→true，00:00→true，00:59→true，01:00→false，01:01→false

### 8.2 手动清单

- [ ] 20:00–01:00 内点"开始学习" → 发 30 词 → 滑完 → 强制弹测验 → 测完进选择页
- [ ] 选择页点"继续下一批"，且未超今日批次上限 → 正常发下一批
- [ ] 选择页点"继续下一批"，但已达今日批次上限 → 按钮禁用/隐藏
- [ ] 21:50 开始一批，滑到 01:05 才滑完 → 允许测完，但测完后"继续下一批"因已出窗口而禁用
- [ ] 非 20:00–01:00 时段打开等级页 → "开始学习"锁定提示，"一般复习""早复习"正常可点
- [ ] 一般复习：多次进入观察"不熟"词和"很久没复习的已掌握词"出现频率明显高于"最近刚复习过的已掌握词"
- [ ] 一般复习测验答错已掌握词 → 状态掉回不熟 → 下次一般复习/早复习能捞到
- [ ] 完成 1 批（滑卡+测验）即触发晚打卡 ✓，不要求刷满当日全部批次
- [ ] 直接访问 `?session=learn` URL（非窗口内）→ 显示锁定页，不进卡片流程
- [ ] 剩余未学词不足 30 → 按实际数量发批，测完不出现"继续下一批"

## 9. 明确不做（本 spec 范围外）

- **词库品类扩展**（形容词/副词/拟声词/综合高频词）+ 用户自选词性组合入口 —— 下一轮单独 brainstorm，需要先确认词库数据来源
- 完整 SM-2/FSRS 间隔算法（一般复习只用简化权重启发式）
- 批次大小 / 学习窗口时间可配置化
- 强制测验及格线（分数门槛）
- 学新 session 断点续做（测验中途退出不保存进度）
- 推送通知 / 跨设备同步 / 成就系统
