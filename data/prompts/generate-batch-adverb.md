# N1/N2 副词 Card Batch Generation Prompt

改编自 `generate-batch.md`（动词版），用于生成副词批次。和形容词版本的关键差异：不写 `type`/`transitivity` 字段；`word` 可能等于 `kana`（纯假名副词，如 うっすら）也可能不等于（有汉字形式，如 飽くまで/あくまで），两种情况都正常，不强制统一。

## Input

一份 JLPT 指定级别的常见副词列表（word/kana/日语释义，一行一个），或调用方直接给出这份列表——不要求自己汇总。

## Output

JSON 对象 `{ "version": 1, "cards": [...] }`，每张卡片符合下面 schema：

- `id`（number）：调用方指定起始偏移量后的 1-based 序号
- `word`（string）：副词书写形式（有汉字写汉字，纯假名副词就等于 `kana`）
- `kana`（string）：平假名读音，仅 U+3040-309F + 30FC
- `accent`（string|null）：不确定就填 `null`
- `type`/`transitivity`：不写这两个字段（副词不适用）
- `meanings`（string[]）：1-4 条简洁中文释义
- `mnemonic`（string）：**短语叙事体助记法**（沿用动词/形容词版本的三关标准：音准 + 短语连贯 + 含义钩子），词块必须是真实可查证的日语词，拼接短语必须是真实存在的日语说法，不能是凑巧对上音的编造词。如果实在凑不出干净的多词块短语，可以退回到"直接用这个词本身的真实汉字读音做锚点，交叉引用另一个用同一汉字的真实词汇"这种更朴素但站得住脚的写法（参考形容词文件里 id6 訝しい / id34 執拗 的处理方式），不要为了凑短语编造不存在的词。
- `examples`：**恰好 2** 个对象，每个 `{ jp, cn }`，要是自然、母语者会这么说的真实用法，不要出现"这个词单独做谓语"这种别扭搭配（比如不能说"膨張だ"，要说"膨張している"）。

## Quality checklist

- [ ] 助记法过三关：音准 + 短语连贯 + 含义钩子，或者用朴素的真实汉字读音锚点
- [ ] `kana` 字段纯平假名（跑 `scripts/validate-cards.js` 校验）
- [ ] 不写 `type`/`transitivity` 字段
- [ ] 例句是母语者会说的自然搭配，不是生造的谓语用法
- [ ] 如果输入列表已经给了日语释义，翻译成中文释义时要准确，不要漂移原意
